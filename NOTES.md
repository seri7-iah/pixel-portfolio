## Built in Phase 3b-1 (parallax, palette cycling, particles)
- **Shared scroll velocity:** new `src/lib/scrollSpeed.js` turns real scroll distance into a 0..1 speed, normalised at 2.6 px/ms and smoothed with `1 - exp(-ms/110)`, so it ramps up and eases back without a second state machine. One passive `scroll` listener and one passive `resize` reset are refcounted: the first world effect attaches them, the last release removes them. Nothing here is React state.
- **Parallax:** new `src/lib/sceneFx.js` (`useSceneFx`) finds the `[data-parallax]` layers inside a section and writes `translate3d(0, offset, 0)` from one viewport progress value (-1..1). Offsets are rounded to 4px on desktop and 3px at 600px and below, so every layer lands on the pixel grid. Two existing scenery layers per world move at different speeds: Home sky 48 / back hill 16, Cave ceiling stack 32 / cave glow 16, Ember ceiling stack 32 / ash 16, Void cream stars 32 / rock two 16. The cave and Ember stacks are new `span` wrappers inside the existing decor, so the rock, light edge, glowing seam, stalactites and drips translate as one piece and cannot slide apart. Ground strips, creatures, copy, dialogue boxes, the portrait and the signpost are untouched.
- **Palette cycling:** the same hook paints CSS custom properties on the section in hard 125ms steps (8 fps) from the shared ticker, so there is no CSS animation duration and no React render. Neighbouring pixels read different variables, which puts them on different offsets:
  - Home: new `.cycle-stars` span, nine box-shadow pixels, 3 cream shades (`#f4e9c1`, `#f0ead2`, `#c7c0b1`).
  - Ember: lava pools (body plus a 4px pixel row), three cracks and two drips cycle 4 shades (`#ff7a1a`, `#ffd447`, `#a4573c`, `#4a221b`). Pools two and three start on different variables, and the old pool and crack gradients were replaced by solid fills plus pixel rows.
  - Void: both glint clusters cycle 3 violets (`#b58cff`, `#e0ccff`, `#7d5fa8`), including the 760px override.
  - Speed: the phase advances by `delta * (1 + scrollSpeed)`, so cycling reaches 2x during a flick and eases back to 8 fps. Pausing freezes the phase and the shades where they are.
- **Particles:** new `src/lib/particles.js` and `src/components/ParticleField.jsx` draw one section-sized canvas with `fillRect` at rounded coordinates, 4px squares on desktop and 3px on phones. About has ash rising, Projects has dust falling, Contact has glints drifting, Home has none. Desktop counts are 44 / 36 / 22 (all under 60); phones use 0.55 of that (24 / 20 / 12, all under 30). Particles wrap, speed up to 1.3x with scroll velocity, and stay above the bottom 160px so no speck draws on a ground strip. A `ResizeObserver` keeps the backing store matched to the CSS box.
- **Gating and layers:** each canvas starts only while its section is on screen, creatures are not paused and the system does not prefer reduced motion; stop unsubscribes from the ticker, releases the scroll-speed refcount, empties the field and clears the canvas. The canvas is the section's first child at `z-index: 0`, under decor (1), creatures (1) and copy (2), with `aria-hidden="true"` and `pointer-events: none`.
- **Reduced motion:** the sections read `systemReducedMotion` directly, so "Play anyway" cannot re-enable decorative FX. No parallax is written, the CSS also forces `transform: none`, particles are hidden and never started, and the palette variables are painted once at index 0 (static pleasant shades).
- **Safety:** only `transform`, canvas pixels and CSS custom properties are written; no width/height/top/left/opacity animation, no per-frame React state, and no gradients or blur added. Every world keeps its two layers at 360px, and horizontal overflow is unchanged because the scenes already clip.
- **Verification:** `npm run lint` and `npm run build` pass (48 modules). Static checks confirm passive listeners with refcounted removal, no per-frame `setState`, reduced-motion gating, and no new `gradient` or `blur` declarations. No browser pass yet.

## Built in Phase 3c-art (sprite lighting)
- **New module:** `src/lib/spriteLight.js` bakes a lit copy of a text-grid frame into an offscreen canvas at the current pixel scale (4 desktop / 3 phone). It caches per palette, sprite, frame, scale, world, accent and glow tone, so a frame is computed once and reused. `imageSmoothingEnabled` is off and every mark is a whole `scale`-sized square. The art itself, its palette letters and its grids are unchanged.
- **Pass order (a-e):**
  - **a. Outline:** every transparent cell touching a filled cell (up/left/right/down, source snapshot only, so no second ring) gets a 1px outline in a very dark tint of that neighbour at 35% of its lightness, same hue, lightness floored at 0.05 so it is never pure black.
  - **b. Shading:** filled cells become one step lighter when the cell above or left is empty/outline, one step darker when below or right is, and keep the base tone otherwise. Every palette letter gets one tone ladder: dark, base, light, bright (four steps, no gradient), derived once per palette in HSL.
  - **c. Emissive:** letters in the `EMISSIVE` map get the bright tone (one step up) and a 1px halo in a lighter tint of their own color on checkerboard cells only (`(x + y) % 2`). The halo may sit on transparent, outline or filled neighbours, which is what makes it read as a hard dither.
  - **d. Rim light:** the lit side (top edge, plus a dithered left edge) is tinted 30% with the section's existing accent variable: Home uses `--line` (pale moonlight blue), Cave/Ember/Void use `--accent` (teal/orange/violet). Read from `getComputedStyle` on the closest `.scene`, never a new palette.
  - **e. Pulse:** emissive sprites pre-bake two glow tones (normal and hot) and swap them every 500ms from the shared ticker (about 2 fps). No new ticker and no pixel work during the swap; it is one `drawImage` of an already cached canvas.
- **Emissive map (art-owned, colors untouched):** Bonemoss `e y` (eye, shoulder crystal), Emberimp `e f t` (eye, hot claw/core, ember tail), Ashwisp `R f m` (inner glow, core, floating embers), Gloamer `e E` (eye slit), Starmote `s S g` (star core, bright center, glints), Emberwing `e E x X c C V t g` (eye, eye trail, shards/cracks, underbody glow, tail tip, motes). Pix, Gloop, Foxel and Mossling have no emissive letters; they still get outline, shading and rim light.
- **Integration:** `Sprite` gains `light`, `world` and `pulse` props. `Critter` and `FloatCritter` pass their `name` as the sprite id, `PixHero` passes `pix` (all side, front, back and 3/4 view frame sets), and `EmberwingDragon` passes `emberwing` with `world="void"`. `CreatureScene` computes one world per zone (`home` / `cave` / `ember` / `void`) and `pulse = active && !fxReduced`.
- **No layout shift:** the baked canvas is 1 source pixel bigger on every side. A new `.sprite-box` wrapper keeps the original `cols × rows` footprint and the canvas sits at `-scale` on both axes, so the art starts and ends exactly where it did. Feet, centre, shadow, hitbox, lane maths, facing flips, hint alignment and the dragon's flight bounds are untouched. Only the outline protrudes outside the old box.
- **Untouched:** `WishStar`, `PixelButton`, the Press Start 2P headings and all text never receive `light`, so they draw with the old one-pixel path. No creature source grid, palette, halo, shadow, flip or motion code was changed. No new dependencies.
- **Gating:** the pulse runs only while the zone is awake, creatures are not paused and the system prefers motion (`fxReduced`), so "Play anyway" cannot re-enable it. Turning pause or reduced motion on stops the subscription and repaints the static first tone; off-screen zones release it too.
- **Verification:** `npm run lint` and `npm run build` pass (54 modules). A Node canvas stub baked all 89 creature frames (including every Pix view and both Emberwing sets): every canvas is `(cols + 2) × (rows + 2)` at 4x, every fill is a whole 4px square inside the padding, no tone is pure black, both glow tones exist for emissive sprites and the cache returns the same canvas object without redrawing. A generated before/after PNG sheet (8x art pixels) was read back to judge the outline, shading ratio and glow density; nothing in `src/` adds `blur`, `filter`, `gradient` or an opacity halo. No browser pass yet.

## Fixed in Phase 3c-art (notice reaction restored)

- **What broke:** the "!" reaction still fired on the first reveal of each world but it was invisible. Before 3c-art, `Sprite` kept a 1:1 backing store (`width={cols}`) and let CSS scale it up (`width: cols * scale`). ## Built in Phase 3c (dithered descent)
- **Three bands, in normal flow:** new `DescendBand.jsx` plus `src/lib/dither.js`. One band sits between each pair of sections inside `<main>`, so it adds its own 200px (120px at 600px) instead of overlaying anything: copy, the dialogue box, the portrait, the signpost, the ground strips and the creature lanes are all untouched, and 360px has no horizontal overflow because the band is a block with a clipped canvas. No section padding, no negative margins and no `scroll-margin` were needed: each anchor still lands on the section's own top edge, with the band entirely above it.
- **Ordered dither, not a fade:** `BAYER8` is the classic 8x8 matrix (0..63, unique). One threshold per level flips cells to the lower colour: `level / 15 * 64`, so level 0 is 100% upper and level 15 is 100% lower, with 14 steps between them (0, 5, 9, 13, 18, 22, 26, 30, 35, 39, 43, 47, 52, 56, 60, 64 of the 64 cells). Every cell is a hard square at the current pixel scale (4x desktop, 3x phone), `fillRect` runs on integer device-pixel coordinates, and only the two seam colours are ever assigned to `fillStyle`. No gradient, blur, opacity, alpha or filter appears in either new module or the new CSS.
- **Scroll to level:** `bandLevel(progress)` maps `progress = (viewportHeight - bandTop) / (viewportHeight + bandHeight)` to `floor(progress * 16)` and clamps: 0 while the band is still below the fold, 0.5 when it is centred, 1 once it has fully passed. The band therefore reads as the upper world before you reach it and as the lower world after it, and the stipple advances in visible steps on the way through.
- **Redraw only on a level change:** one passive `scroll` listener per band, coalesced into `requestAnimationFrame`. The handler compares the new level with the last and returns before touching the canvas, so a continuous scroll repaints at most 15 times per crossing. A resize re-measures; only a changed backing store (viewport size or pixel ratio, which clears the canvas) forces one extra repaint, otherwise the same level guard applies. `cancelAnimationFrame` and both listeners are removed on unmount. There is no ticker and no React state.
- **Seam colours from the live palettes:** each draw reads the two sections with `getComputedStyle`: Home `--dirt` to Cave `--cave-wall-deep`, Cave `--cave-floor` to Ember `--ember-rock-warm`, Ember `--ember-rock` to Void `--void-bg-top`. Level 0 matches the last visible row of the world above (Home's 12px `--dirt-dark` ground edge, the cave floor, the ember ground) and level 15 matches the first row of the world below (the cave and ember ceiling tops, the void background behind the burnt lip), so neither end of a band introduces a new hard line. Nothing is copied into JS, so the Home band will follow the future Night/Day toggle.
- **Lips:** Home to Cave and Cave to Ember get a two-row ragged rock lip at the top: a full shadowed underside row, a hand-drawn 24-cell tooth pattern (clumps of two to four with gaps) and sparse lit pixels on the tooth row, in that world's own rock tokens (`--dirt-dark`/`--dirt-light`, `--cave-rock`/`--cave-stone-light`). Ember to Void gets floating rock dust instead: single cells over the top three rows, thinning with depth, in `--void-rock-shade`/`--void-rock-warm`, placed by a 32-bit `Math.imul` hash so the pattern is identical on every redraw and cannot flicker.
- **Entry beat:** the first time a band's level reaches 8 (the seam centred), `App` adds `is-thumping` to the `.app` wrapper: 2px down and back in two frames, 120ms, whole pixels, `transform` only, desktop only. It is gated in JS (`fxReduced`, `spriteScale <= 3`, never while one is already running) and again in CSS by `@media (prefers-reduced-motion: no-preference) and (min-width: 601px)`. `animationend` is filtered to `event.target === app` before the class is removed. The first frame never counts, so a reload or hash jump that starts past a band cannot thump; a resize cannot either. No sound.
- **Reduced motion:** each band paints one still frame at level 8 and registers only a resize listener, so there is no scroll listener, no rAF and no thump. Like 3b this reads `systemReducedMotion` directly, so "Play anyway" cannot re-enable it. "Pause creatures" never touches the bands.
- **Untouched:** creatures, sprites, palettes, scenery content, the 3a-fix reveal and the 3b effects. No new dependencies, no assets, no sound.
- **Verification:** `npm run lint` and `npm run build` pass (56 modules, `index-nhO1Y2jE.js` / `index-BzIct4BV.css`). A Node harness ran 39 checks on the real painter and sources: the matrix is a unique 0..63; level 0 flips 0 cells and level 15 all 64; the counts only grow; only the two seam colours are painted; every `fillRect` is integer and exactly one cell; the same level repaints identically; the rock lip and the dust specks stay in the top rows and never form a bar; 400 scroll positions give exactly 16 levels and 15 changes; no `gradient`/`blur`/`opacity`/`alpha`/`filter` string exists in the new code or CSS; the reduced branch has no scroll listener; scroll/resize removal and frame cancellation are present; the band has no `useState`/`setState`. A Vite SSR render of the real `App` shows `section#home` to band to `section#projects` to band to `section#about` to band to `section#contact` to footer, three `aria-hidden` band divs that contain only a canvas and no text, and the signpost's four hrefs matching the four section ids. No browser pass yet.

## Built in Phase 3b-2 (living world)
- **Notice reaction, shared:** new `src/lib/notice.js` holds the 700ms beat, the 150ms stagger, the whole-pixel hop (`noticeLift`, 4px desktop / 3px phone), the floating extra bob (`noticeBob`) and `faceTowardMiddle`. New `NoticeBubble.jsx` is a 10x14 text-grid "!" (amber `#ffb347`, highlight `#ffd98a`, 1px dark outline `#1a1208`) drawn through the existing `Sprite`, so it scales at 4x/3x with the creature art and stays on the same pixel grid. No sprite or palette was redrawn.
- **Once per section, per load:** each `CreatureScene` receives `sectionRevealed` from the existing one-shot `useReveal` observer (Home, Projects, About, Contact) and passes `noticeArmed` down. Every creature runs `useNoticeSchedule`, which starts its own 150ms-staggered countdown only while its zone is awake, so a reaction is never spent off screen, while paused or under reduced motion. The `started` ref then makes the greeting one-shot for the page load.
- **How the beat is driven:** on start the creature stops its wander plan, faces the screen middle and adds `.is-on` to the bubble; the hop/bob is written from the shared ticker straight to the sprite wrapper's `transform`. ## Decisions
- JavaScript, not TypeScript. Original CSS pixel art only; no downloaded or third-party art.
- Fonts are installed via npm (`@fontsource/press-start-2p`, `@fontsource/atkinson-hyperlegible`), never downloaded from the internet.
- One continuous world beats four boxed sections. Text sits on the scene; only character speech gets a border.
- The site keeps one visible border treatment: a 4px solid border on `DialogueBox` (including its header divider). The portrait frame is the one other framed object, as a wooden picture frame. Everything else uses unboxed shapes, backgrounds and stepped `box-shadow` layers.
- Theme colors are CSS variables; composite pixel shadows are written directly in component CSS so scene-local variables recompute correctly.
- Home keeps one shared right column for navigation and the portrait instead of a third middle column. The moon owns the top-right sky; the walking strip stays empty of UI.
- Sprites are canvas-backed text grids (16x16 critters and 16x32 people) so a new mob only needs frames plus a palette. Wandering lives in `Critter`; movement is written to `style.transform` and never through React state, so the frame rate stays flat. A future controlled mode can sit on the same component.
- Each section owns its creatures and ground strip. The zone uses one IntersectionObserver to freeze off-screen creatures, and the walking band is measured from the section's bottom so the same lane maths works for every strip.
- All side-view characters are built from part compositors on their text grids. Pix keeps its layered part stamps; Gloop uses row spans so it can squash and stretch; Foxel fills blocks and outlines the silhouette once; Mossling and Bonemoss use rectangular limbs plus a stamped head, leaf or skull. The old front-view body template is gone.
- Pix's parts are precomposed into 16x32 frames at module load rather than rendered as separate DOM layers. The limbs still move independently in the art pipeline, and the runtime keeps one crisp canvas per creature.
- Boots are a separate layer from the pants, so the body can bob without lifting the planted foot.
- Walk animation is a pure function of distance travelled. Speeds and frame rates can change without retuning the animation, and off-screen or paused creatures do not advance.
- Facing flips only the sprite canvas. The hint and any future label stay outside the flipped element.
- Only control changes Pix's view. The eight-direction helper returns `null` for opposite keys so the last pose survives, and the renderer reads the side pose again as soon as control is released. New 3/4 art is drawn facing right once and mirrored, which keeps the art file small.
- Depth movement reads one normalized key vector shared by smooth control and the reduced-motion step. `Math.SQRT1_2` on both axes keeps a diagonal at straight-line speed, and tap-to-walk uses the same `seekVelocity` path so touch cannot outrun the keyboard.
- The star field is kept out of the text by owning the top band (80px Home padding) and the far gutters instead of scattering dots behind the copy.
- The page is one descending world, so each section owns a palette scope and a fixed cast instead of the page owning one theme. Home keeps the Night/Day toggle; Projects, About and Contact keep their palette permanently.
- Docs are written before the art for each new world (2e-1), so Ember and Void scenery has a written color, roster and anti-lookalike contract to build against. Docs-first is cheaper than reworking art that drifted.
- Each world owns its palette scope and its scenery. Palette classes stay variable-only so the same scope can dress a section, a footer or a future dialog without dragging layout along.
- Ember and Void scenery is pure CSS: banded gradients, `clip-path` rock, stepped `box-shadow`/`drop-shadow` glows. No images. Part A adds CSS-only motion behind an `is-live` class so reduced motion, the pause button and off-screen sections can stop it without touching the ticker.
- Scenery motion is gated by `is-live` on the section, driven by a shared `useOnScreen` hook. The animation loop stays in CSS; JS only toggles the class.
- The About-to-Contact seam gets the stepped Ember-rock lip in the scenery pass where the seam belongs, instead of waiting for the creature pass.
- Phone scenery hides wide layers instead of shrinking them behind the copy. The ceiling, ash, one edge glint and the ground caps carry the scene at 360px.
- The 7-mob desktop limit is kept as an awake/visible budget, not a total-cast limit. All 10 creatures exist in their zones; freezing off-screen zones means only one zone is awake at a time (at most 3 creatures, plus the dragon). Phones use one creature per zone to respect both the 4-total and 2-per-section limits.
- Floating creatures get their own `FloatCritter` rather than a mode inside `Critter`. The ground wanderer's distance-driven walk, arrival easing and lane clamp do not apply to a bob, so keeping the two motion models apart avoids weakening either one.
- Floating bodies bob on whole pixels and keep the existing ground wrapper and shadow. The shadow stays put while the body lifts, which reads as hovering without any new shadow logic.
- Section reveals live on the section as Motion variant parents, so each label, heading, paragraph and link opts in with one `variants` prop and the 80ms stagger comes from DOM order. This avoided adding wrappers that could disturb the existing grid areas and safe zones.
- The reveal uses Motion's built-in `steps(4, 'end')` easing instead of smooth bezier timing. Four hard hops keep the motion on the 4px grid and match the pixel style; a 16px slide with four steps lands exactly on 16/12/8/4/0.
- `DialogueBox` and `PixelButton` became Motion roots so their existing `...rest` spread can carry `variants`. This keeps reveal props out of the DOM and avoids wrappers around boxes and links.
- Reduced motion mounts sections with `initial="show"` and no `whileInView`, rather than animating with zero duration. Final values are applied in the first paint, so there is no hidden frame and no stagger delay.
- Palette cycling writes CSS variables from one shared ticker instead of CSS keyframes. A keyframe animation cannot accept a live speed multiplier without jumping the phase, and pausing becomes one guard instead of `animation-play-state` on dozens of pixels.
- Two existing scenery layers per world parallax instead of adding new art. The layers were chosen because they already exist at 360px, so the phone keeps the same depth cue without extra scenery.
- Particles are plain canvas with a 1x backing store and `fillRect`, not CSS dots or a sprite sheet. Integer coordinates keep every speck hard, and one module serves all three fields.
- Each field starts from the existing `ParticleField` active prop, and the scroll-speed reader is refcounted, so four sections can never double-apply velocity or leave listeners behind.
- Reduced-motion FX read `systemReducedMotion` rather than the effective preference, so "Play anyway" stays a creature-only escape hatch.
- Pause is read through a ref inside `useSceneFx`, so freezing the palette does not tear down and rebuild parallax.
- Sprite lighting is baked into an offscreen canvas, never applied with CSS filters: `filter`/`drop-shadow` would blur the pixel grid and would cost work every frame. Two glow tones are pre-baked so the pulse is a cached `drawImage` swap.
- The lit canvas is padded one source pixel and mounted inside a fixed-footprint `.sprite-box`. That keeps every existing lane, hitbox, shadow and flight-bound number valid instead of retuning motion for a bigger canvas.
- Emissive letters live in `spriteLight.js` rather than in the palettes, so the pass can mark eyes/cracks/flames without changing the art contract. A new creature only adds one letter list.
- The pass is applied opt-in through `Sprite` (`light` + `world`), so the wish star and all text keep the old one-pixel path without a second sprite component.
- The notice bubble opted into the pass but not into the pulse: it is a 700ms beat, so a 2 fps swap would mostly run while it is `display: none`. Only the bubble's `h` glint is emissive, which keeps the dark "!" glyph readable instead of dithering it.
- The bubble's hand-drawn near-black ring was replaced by its own amber. A palette ring that is already the darkest letter hides the pass's shading (every neighbour is filled), so the bubble would have stayed flat; letting the pass draw the silhouette is what makes the four-tone amber ramp appear.
- Unlit sprites keep a 1:1 backing store scaled by CSS, while lit sprites are baked at CSS scale. Those are two different size contracts in one component, so they are named separately (`pixelWidth`/`pixelHeight` vs `cssWidth`/`cssHeight`) instead of sharing one number.
- The descent bands are in-flow siblings with their own height, not overlays. That makes "never covers text, dialogue, portrait, signpost, ground strip or creature lane" a property of the layout instead of a stack of hand-tuned offsets, and it keeps every anchor landing on the section's own top edge with no `scroll-margin` to maintain.
- One uniform Bayer threshold per level, not a threshold that also varies with height: the band itself is the fade, and a row bias would break the exact 100% upper / 100% lower states that let both ends merge into the scenery.
- Each band's two colours are the last visible row of the world above and the first row of the world below, read from the live sections. Copying the palette into JS would drift, and reading it also lets the Home band follow the future day theme.
- Levels use `level / 15`, not `level / 16`, so level 15 is exactly all-lower and level 0 is exactly all-upper; `level / 16` would leave a stray upper row in the seam.
- Cell size is `round(scale * dpr)` in device pixels with whole-pixel `fillRect`s. A CSS-pixel backing store would be resampled by the browser on fractional-ratio displays, and a resampled cell edge is exactly the antialiasing the pixel rule forbids.
- The "level unchanged, return" guard is the entire animation budget: no ticker, no per-frame work and no React state, just 15 canvas repaints per crossing.
- The entry beat is gated twice (JS and a CSS media query) and fires on a level transition rather than on mount, so a reduced-motion visitor and a reload that starts mid-page can never get one.

## Lessons
- Fontsource keeps self-hosted fonts inside the bundle and the Vite build fingerprints them automatically.
- Scoping theme tokens to `.scene--cave` keeps the Cave palette on Projects without changing the root theme.
- Lightweight pixel scenery is practical with `clip-path` stepping, `box-shadow` blocks and layered absolutely positioned spans; no image pipeline is needed.
- The global `img { image-rendering: pixelated }` rule must be overridden per image when a real photo should stay natural.
- Percentage `clip-path` shapes scale with the box; px-based ones do not, so the placeholder silhouette uses percentages for its phone size.
- `display: contents` lets the desktop right-column stack become individual grid items on phones without duplicating markup.
- One shared rAF ticker (instead of a timer per sprite) makes "pause when the tab is hidden" a single rule and keeps two characters cheap.
- A text-grid art file is fast to iterate on: lengths can be checked and printed as ASCII in Node, so no browser is needed to proof the sprites.
- Give the back foot the darker shade and the front foot the lighter one; the two legs stay readable even when a side-view walk crosses them. Starting the legs one row under the hem hides the hip joint without extra art.
- Precomposing layered parts into text-grid frames keeps the 16x32 contract while still letting each limb move on its own. Keeping the boots out of the bob was the fix that finally kept the feet planted.
- Exponential velocity easing (`1 - exp(-rate * dt)`) is frame-rate independent and gives both the start ramp and the stop glide without a separate acceleration state machine.
- Advancing a walk phase with `distance / stride` is simpler than syncing a timer to speed, and it naturally freezes the feet when a creature is blocked or paused.
- Per-section IntersectionObservers mean the shared ticker really does stop when every zone is off screen; only Pix's control state and each zone's ResizeObserver stay alive.
- Writing the roster per zone exposed the arithmetic: 10 desktop creatures against a 7-mob cap, and 8 phone-capable creatures against a 4-mob total. The cap can only hold as an awake/visible budget or by trimming, so roster plans need the maths checked at the same time as the cast list. Phase 2e-3 settled it: all 10 on desktop, one per zone on phones.
- A floating sprite can share the ground creature's wrapper and shadow; only the body needs a separate lift/bob transform. That kept the new component small and preserved pause, reduced-motion and off-screen freezing without touching `Critter`.
- Swaying on a sine with a per-creature phase gives a natural drift without a target-picking state machine. Initialising the phase in the placement pass avoids a first-frame jump when the zone wakes.
- Hard-stop `linear-gradient` bands read as stacked rock and sky; a single soft radial gradient would have looked airbrushed and broken the pixel style.
- Palette variables declared on the same element as the background work because both rules match that element; the trap is assuming the section's own CSS file has to define them.
- Hiding wide decor at the existing 1024/760 breakpoints is cheaper than trying to keep it clear of a text column that reflows between 760 and 1024px.
- `animation-play-state: paused` on the default state and a parent `.is-live` class is a cheap way to freeze CSS-only scenery off-screen or paused without a JS animation loop.
- A shared IntersectionObserver hook avoids duplicating the sentinel logic between `CreatureScene` and `App`.
- `box-shadow` glows are clipped by the element's `clip-path`; `filter: drop-shadow()` is the way to make a hard pixel glow follow a stepped shape.
- `vh`-based ash offsets only cover one viewport band, so the field needs a layer near the top, middle and bottom of a tall section.
- A custom stepped easing does not have to end at 1: Motion's JS animation substitutes the exact final keyframe when the tween finishes, so `steps(4)` can hold at 0.75 and still land on the real target.
- Framer Motion variants propagate through plain DOM wrappers via React context, so a section can own the reveal state without every intermediate div becoming a motion element.
- CSS variables are a clean palette-cycle bus: writing `--cycle-*` on the section updates every pixel that reads them without React, and each shadow pixel can read a different variable for offset at no cost.
- Rounding the offset rather than the whole transform keeps parallax on the pixel grid: `Math.round(value / unit) * unit` works at both 4px and 3px, and `translate3d` keeps it on the compositor.
- A shared smoothed velocity is more reusable than per-effect damping. Normalising once keeps the palette cycle and the particles accelerating together.
- Canvas specks should size from the CSS box, not `devicePixelRatio`, when the art language is fixed pixel squares. A 1x store keeps the 4px grid exact and matches the sprites' CSS scaling.
- A refcount is the simplest way to share global listeners across independent effects without a context or a store, and it makes "remove the listener with the last consumer" a single rule.
- Deriving a small tone ladder in HSL per palette letter keeps outline and shade in the same hue, but the lightness needs a floor: without it, dark materials snap to pure black and lose the tint.
- A checkerboard glow has to be decided in source-pixel space (`(x + y) % 2`) before scaling; drawing it any other way turns into a soft pattern.
- Baking at mount and caching by palette/frame/scale/world keeps a per-pixel pass out of the animation loop; the pulse only swaps between two already-finished canvases.
- A "missing" element can still be firing: the notice regression was a 4x size drop, not a broken schedule. Compare the rendered box (backing store vs CSS size) before touching the timing code, and check every consumer of a shared component when its size contract changes.
- A custom property has to be read from the element that scopes it: `getComputedStyle(section).getPropertyValue('--x')` gives that world's value, while reading it off a band between two sections would silently fall back to the root palette.
- Setting `canvas.width`/`canvas.height` clears the canvas, so a resize path has to force one repaint; the level guard would otherwise skip it and leave an empty band.
- `Math.imul` keeps a seeded pixel pattern identical everywhere. Multiplications of large hashes lose low bits once they leave 32-bit integers, which is what makes some hand-rolled hashes differ between engines.
- A band between two worlds can only be judged by its two ends: pick the colours from the pixels that actually touch it, not from the palette's headline colour, or the seam gains a new hard line.
